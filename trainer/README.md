# Isolation Forest trainer

`train.py` trains the extension's inference-only Isolation Forest from a SQLite
database and writes a JSON model that can be committed or copied into the
extension's `model/` directory.  The exported JSON contains only tree topology
and training metadata; it never contains passwords, key names, or the source
sessions.

## Why SQLite rather than the extension's IndexedDB?

The browser's IndexedDB is intentionally private to a browser profile, so a
Python process cannot safely open it directly.  The extension should export
the `keystroke_sessions` records selected by the user as JSON, and the
following command imports that export into the trainer's SQLite database.  A
backend can also write the same table directly.

```powershell
py -m pip install -r trainer/requirements.txt
py trainer/train.py import --database trainer/sessions.sqlite --input password-anomaly-sessions.json
py trainer/train.py train --database trainer/sessions.sqlite --output model/isolation_forest.json
```

The JSON import is an array of session objects, or an object whose `sessions`
property is that array.  Each valid record needs:

```json
{
  "id": "optional-uuid",
  "capturedAt": 1730000000000,
  "keyHoldDurations": [81.2, 65.0],
  "keyTransitionDurations": [42.1],
  "passwordEntryDurationMs": 230,
  "backspaceCount": 0
}
```

All timing arrays are retained as individual values in the database.  No
per-user averages or baseline samples are stored.  Training derives a bounded
feature vector in memory only: counts and min/max/median/90th-percentile for
each timing array, plus entry duration and deletion count.  This lets sessions
of differing password lengths be used without persisting aggregate profiles.

At least two valid sessions are needed.  For a stable model, use substantially
more normal sessions (the default cap is 256).

## Export format and JavaScript inference contract

The output has `format: "isolation-forest-tree-v1"`.  Each tree uses this
recursive shape:

```json
{"feature": 3, "threshold": 7.5, "left": {"size": 1}, "right": {"size": 2}}
```

Leaf nodes have only `size`; branch nodes have `feature`, `threshold`, `left`,
and `right`.  `feature` indexes `featureNames`.  The extension must form the
feature vector using the ordered `featureSchema`, follow `value < threshold`
to the left, and add `c(size)` at a leaf, where `c(0)=c(1)=0`, `c(2)=1`, and
`c(n)=2*(ln(n-1)+0.5772156649)-2*(n-1)/n` otherwise.  Its raw anomaly score is
`2 ** (-averagePathLength / c(sampleSize))`; mark a session anomalous when it
is at least `anomalyThreshold`.  `offset` is included to reproduce sklearn's
`decision_function` when needed (`decisionFunction = -rawScore - offset`).

Use an export generated by the same feature schema version as the extension.
`train.py` rejects malformed sessions rather than filling missing timing data.
